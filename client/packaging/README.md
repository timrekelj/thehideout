# Packaging the desktop client

## macOS (arm64): done

```sh
cargo install cargo-packager --locked   # once
client/packaging/macos/build.sh
```

Output goes to `client/dist/macos/`: `thehideout.app` and `thehideout-<version>.dmg`.

- **Bundle**: `cargo-packager`, configured in `[package.metadata.packager]` of
  `client/desktop/Cargo.toml` (bundle id `si.zabit.thehideout`, category social networking,
  minimum macOS 11.0, which is what the arm64 build targets). `macos/Info.plist` adds the
  microphone and camera usage strings and `NSHighResolutionCapable`.
- **Icon**: `macos/AppIcon.icns`, generated by `macos/make-icon.sh` from `make-icon.swift`
  (original artwork drawn in code, in the default accent). Only rerun it to change the icon.
- **Signing**: ad-hoc by default (`codesign --sign -`, hardened runtime, `macos/Entitlements.plist`).
  Ad-hoc builds run on the Mac that built them; elsewhere Gatekeeper blocks them.
  Set `APPLE_SIGNING_IDENTITY` for a Developer ID signature. Also set `NOTARY_PROFILE`
  (a `notarytool store-credentials` profile) or `APPLE_ID` + `APPLE_APP_PASSWORD` +
  `APPLE_TEAM_ID` to notarize with `xcrun notarytool submit --wait` and staple the app and the dmg.
- **Entitlements**: audio input and camera. `allow-unsigned-executable-memory` is left out:
  libwebrtc is statically linked, ahead-of-time compiled code and nothing in the app generates code
  at run time; the ad-hoc, hardened-runtime build launches without it.
- **Screen sharing** has no Info.plist key. macOS asks for the grant under System Settings >
  Privacy & Security > Screen & System Audio Recording the first time someone shares a screen;
  the app must be restarted after granting it. The grant is tied to the app's signature, so an
  ad-hoc rebuild asks again; Developer ID builds keep it across updates.
- **Session token** stays in the 0600 `prefs.json`; the Keychain is not used. Keychain items are
  tied to the app's code signature, so with ad-hoc signing (and every debug rebuild) macOS would
  prompt for access each time the binary changes.
- **Crash logs**: `~/Library/Application Support/thehideout/crashes/`, the last five panics.
  Nothing is uploaded.
- **Version check**: the client sends `x-thehideout-client: desktop/<version> (<os>)`. A server
  answer of FAILED_PRECONDITION "client too old..." shows the "Update required" screen, linking
  to https://thehideout.zabit.si/download.

## Windows and Linux: not done yet

No installers, icons or signing exist for them. The client code builds there in principle
(Rune has Windows and Linux shells), but libwebrtc linking, the camera backend and packaging
(MSI/NSIS, AppImage/deb) are untested.
